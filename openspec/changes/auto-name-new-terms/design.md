## Context

现状约束有两个来源，现在其中一个已经过时：

1. **词元全覆盖**（P1 起，构建期强制）：术语名分解出的每个词元都必须登记为数据元/限定词 → 保证组合器能为任意术语产出规范名
2. **别名全覆盖**（D9 修复时加入，构建期强制）：每个术语都必须有手写中文别名 → 保证中文可召回

第 2 条在第 1 条落地后成了**冗余的人力门槛**：没有别名的新术语依然有 `canonical_zh`，中文照样可召回；而别名真正不可替代的价值是**补充同义词**（`主体` ↔ Performer）与**数据组别名**（`资源流`），这两者都不需要「每个术语都有」。

## Goals / Non-Goals

**Goals**

- 新术语（由既有词元组成）**无需任何手写内容**即可获得可检索的中文名
- 新术语若含未登记词元，构建**明确失败**并要求登记词元（不允许静默缺名）
- 数据组别名（17 个组）与别名源的**键/格式校验**继续强制
- 提供命名预检入口，让「这个新名字会组合成什么」在写代码前就能问

**Non-Goals**

- 不删除现有 279 条策展别名（它们是同义词层，仍被检索使用）
- 不做中文名的「人工评审工作流」（PR 流程已覆盖）
- 不为既有 279 条别名补同义词（属内容工作，另开）
- 不改检索排序与输出形状（P2/P3 已定）

## Decisions

### Decision 1: 中文名的强制来源从「人工别名」转为「组合结果」

**选择**：构建期硬校验「每个术语 `canonical_zh` 非空」；按术语的别名覆盖不再强制，只报告覆盖率。

**理由**：组合结果由「词元全覆盖」这条更强的结构性约束保证——补一个新词元要写 1 条词表条目（可复用），补一个新别名要写 1 条一次性文本（不可复用）。把强制放在可复用的那一侧，新术语成本从「写中文」降为「零成本（词元已存在）」或「登记 1 个词元」。

**Alternatives**：A. 保留别名强制（拒绝：新术语仍卡人力，且与 `canonical_zh` 职责重叠）；B. 两者都不强制（拒绝：会出现无中文名的术语，回到 D9 的静默 0 命中）。

### Decision 2: `groups:` 段转为必需

**选择**：别名源必须有 `groups:` 且覆盖全部 17 个数据组，否则构建失败。

**理由**：组级中文召回（「资源流」）完全依赖它，没有组合层的替代来源。放宽按术语别名时**收紧**这一条，保证放宽不是净弱化。

### Decision 3: `describe(name)` 是模型层能力，`knowledge compose` 只是它的出口

**选择**：`ElementVocabulary.describe(name)` 返回 `{term, tokens, segments[{token,kind,zh}], composed, unregistered}`；CLI `dm2 knowledge compose` 打印它（支持 `--json`）。

**理由**：描述能力同时服务三处——新术语预检、词表作者排查、以及测试。放在模型层（`kernel`）而非 CLI，避免把逻辑写进命令。

### Decision 4: 「无法组合」不是命令失败

**选择**：`dm2 knowledge compose ZzzThing` 仍返回 `status: success`，`composed` 为空串、`unregistered` 列出未登记词元，退出码 0。

**理由**：这是**诊断答案**而非执行失败——调用方（人或 Agent）要的正是一份「缺哪些词元」的清单。若返回 error 信封，脚本就得用错误处理来表达正常查询。文档与测试固化这一语义。

## Risks / Trade-offs

- **[风险] 放宽后别名层被遗忘** → 构建报告每次都打印「X/279 有策展别名」，且 4 条 P1 对账测试仍要求组合与别名层一致（别名缺失不会让它们失败，但别名写错会）。
- **[风险] 新术语的规范名质量低于人工译名** → 组合名与人工译名的一致性已达实体 100%/关联 96.2%；新术语若有更佳译名，人工别名可随时补充并优先展示。
- **[取舍] `compose` 增加了 CLI 面** → 必须纳入 `test_cli_json_contract.py` 的 `--json` 覆盖，避免成为「未判定的不一致」。

## Migration Plan

- P4 完成后，「新增 DM2 术语」的流程变为：改数据字典 → 跑构建 → 若报「未登记词元 σ」则登记词元 → 中文名自动就绪（别名可选）。
- 既有项目无需迁移（字段与行为不变）。

## Open Questions
